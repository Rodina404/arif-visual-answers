## 0. Context: what we are building and why

**Arif (عارف)** is the AI assistant inside **Qriib**, an Arabic-first, "sovereign AI" product suite made by Tawteen Tech / V.Connct (Egypt). When a user uploads a PDF and asks about it, Arif today replies with a **long block of Egyptian-Arabic text**. The structure is hidden in the prose: comparisons sit inside sentences, steps are not numbered, and numbers have no source.

We are building a **small, demo-ready prototype** that answers the same questions about the same PDF as a **short direct answer plus up to 3 typed visual components**: a chart, comparison card, step cards, table, quiz, flashcards, diagram or formula. The components must be:

- **Grounded.** Every number and factual claim in a chart, table or quiz carries a page number and a verbatim quote, and the server checks it against the PDF's text.
- **Safe.** The model outputs *data* that matches a whitelisted schema. It never outputs HTML or code. Our own React components draw the data.
- **RTL-correct.** Egyptian Arabic (right-to-left) is the default. An English toggle switches to left-to-right.
- **Restrained.** Use no visual when one does not help. Plain text is a valid and often correct answer.
- **Measured.** Every answer shows its tokens, its cost in USD, and its latency.

**Demo PDF:** Wei et al. (2022), *"Chain-of-Thought Prompting Elicits Reasoning in Large Language Models"*, arXiv **2201.11903**. Download it from `https://arxiv.org/pdf/2201.11903` into `fixtures/pdfs/cot.pdf` and record its SHA-256 and page count in `BUILD_LOG.md`. It has many pages because of the appendix (probably about 40). Measure the real count; don't assume it.

**Key screen: "Before vs After".** On the left is a long text-only answer in the current Arif style, generated by the same model with a "plain prose" prompt. Label it clearly: *"Simulated text-only answer (Arif-style)"*. On the right is the visual answer to the same question. Both panels show their own cost and latency.

**Why the architecture looks like this (short justification).** For a reliable 2-day autonomous build, the **primary path** is our own typed component catalog: **Pydantic** on the server, **Zod** on the client, filled by **Gemini structured output** (JSON Schema), and streamed **one validated component at a time over SSE** to pure props-in React components. Here is why we don't build on a framework first:

- Google's **A2UI** (declarative trusted catalogs) is still pre-1.0. v0.9.1 is current and v1.0 is only a candidate.
- **CopilotKit** has renamed its generative-UI hooks between versions, and its RTL support is unverified.
- **OpenUI 1.0** shipped on 2026-10-15 and has no official Python package.
- No end-to-end sample of ADK + A2UI + Gemini + a custom chart and quiz catalog could be found.

AG-UI 1.0 (an event protocol) is stable. So we **name our SSE events after AG-UI events**, and we shape components as flat, ID-keyed entries from a client-declared catalog (A2UI's model). Adopting AG-UI + CopilotKit (+ Google ADK) or an A2UI renderer later is then an optional **stretch phase (Phase 11)**, not a dependency.

**Data sovereignty.** The company stresses running AI inside the client's own environment. All model access therefore goes through a **provider adapter**. Gemini is the default for the demo, and an OpenAI-compatible provider (for self-hosted vLLM, Ollama or llama.cpp servers) must also be possible. Note in the UI and the README that **the demo sends the PDF to Google**, and that production would use a self-hosted provider.

## 3. Architecture

```
Browser (React, Vite build served by FastAPI in e2e/prod; Vite dev server with proxy in dev)
  │  POST /api/documents  (multipart PDF)            → {doc_id, pages, warnings[]}
  │  POST /api/ask  (JSON) → text/event-stream (SSE)  → AG-UI-shaped events
  │  POST /api/ask_text (JSON) → SSE                  → "before" plain-text answer
  ▼
FastAPI
  ├─ upload.py      limits, magic bytes, pdfplumber parse, page text, hidden-text detection
  ├─ grounding.py   normalization + quote/number verification against VISIBLE page text
  ├─ catalog.py     Pydantic component models + JSON Schema export (Gemini-compatible)
  ├─ policy.py      restraint rules (caps, downgrades, ordering)
  ├─ stream.py      incremental JSON parse → emit one component when complete
  ├─ cache.py       answer cache (sha256(pdf)+question+lang+model+prompt_version)
  ├─ metrics.py     tokens, cost (prices.json), TTFT, time-to-first-component, total
  ├─ providers/
  │    base.py           LLMProvider protocol
  │    gemini.py         google-genai, Files API, thinking level, usage metadata
  │    openai_compat.py  self-hosted (vLLM/Ollama) via response_format json_schema; PDF sent as extracted text
  │    mock.py           replays fixtures with delays (MOCK_LLM=1)
  └─ security.py    rate limiting (slowapi), CSP/headers, CORS, request size caps
```

### SSE event envelope (AG-UI-aligned names)

Each SSE message has `event: <TYPE>` and `data: <json>`. Use `fetch` + `ReadableStream` on the client, not `EventSource`, because `EventSource` only supports GET.

| Event | Data | AG-UI mapping |
|---|---|---|
| `RUN_STARTED` | `{run_id, doc_id, lang, model, cached: bool}` | `RUN_STARTED` |
| `TEXT_MESSAGE_START` | `{message_id}` | same |
| `TEXT_MESSAGE_CONTENT` | `{message_id, delta}` | same |
| `TEXT_MESSAGE_END` | `{message_id}` | same |
| `COMPONENT_PLANNED` | `{component_id, type}` (shows a skeleton) | `TOOL_CALL_START` (tool name = component type) |
| `COMPONENT` | `{component_id, type, props, verification: {status: "verified"\|"partial"\|"unverified", dropped_points: n}}` | `TOOL_CALL_ARGS` + `TOOL_CALL_END`; A2UI: one catalog component in a surface update |
| `COMPONENT_DROPPED` | `{component_id, type, reason, fallback_text?}` | custom |
| `WARNING` | `{code, message}` (e.g. `HIDDEN_TEXT_DETECTED`, `FALLBACK_MODEL_USED`) | custom |
| `METRICS` | see section 9 | `STATE_SNAPSHOT` |
| `RUN_ERROR` | `{code, message}` | `RUN_ERROR` |
| `RUN_FINISHED` | `{run_id}` | `RUN_FINISHED` |

Record this table in `docs/protocol.md` (the only extra doc you should create) together with a short note on how a future AG-UI or A2UI adapter would translate it.

## 4. Component catalog (the contract)

Define the catalog **once in Pydantic** (`backend/app/catalog.py`). Export JSON Schema with a script, then **generate the Zod schemas** (`frontend/src/catalog/schemas.ts`) from it with `json-schema-to-zod`, or write them by hand with a test that checks the two stay equivalent. Use `additionalProperties: false` everywhere. Enforce string length limits in Pydantic and Zod, because Gemini does not enforce `maxLength`.

### Shared types

```text
Lang        = "ar" | "en"
Citation    = { page: int ≥ 1, quote: str (10–300 chars, verbatim from the PDF, in the PDF's language) }
BaseComponent = { id: str (c1..c9), type: <enum>, lang: Lang, title: str ≤ 80, reason: str ≤ 140 }
```

`reason` explains to the policy layer and the logs why a visual helps. It is not shown to the user (it's visible only in the metrics drawer).

### Top-level response (what Gemini fills)

```text
VisualAnswer = {
  answer_text:  str ≤ 700 chars   # ALWAYS present; the short direct answer, 1–4 sentences
  language:     Lang
  needs_visual: bool              # false → components must be []
  components:   list[Component], maxItems 3
}
```

### Components

| `type` | Fields | Use when | Don't use when |
|---|---|---|---|
| `text` | `body: str ≤ 1200` (limited markdown: bold, italics, lists; **no links, images or HTML**) | Supplementary explanation that has no structure | Never as the only component; that's `answer_text`'s job |
| `chart` | `chart_type: "bar"\|"line"`, `x_label ≤ 40`, `y_label ≤ 40`, `unit ≤ 12`, `series: 1–2 × {name ≤ 40, points: 3–12 × {label ≤ 30, value: number, citation: Citation}}` | **≥ 3 numeric values that appear in the document** and share one unit, compared across a category or trend | Fewer than 3 numbers, mixed units, or the model would need to compute values |
| `comparison` | `items: 2–4 × {name ≤ 40, summary ≤ 160, attributes: 2–6 × {key ≤ 30, value ≤ 80, citation?: Citation}}`. Keys must be the same set and order across items. | Two to four things compared on shared attributes (e.g., standard prompting vs chain-of-thought) | A single item, or items with no shared attributes |
| `steps` | `ordered: true`, `steps: 2–8 × {title ≤ 60, detail ≤ 220, page?: int}` | An ordered procedure or method | Unordered facts (use `text`) |
| `table` | `columns: 2–6 × str ≤ 30`, `rows: 2–12 × {cells: list[str ≤ 60] (len = columns), citation: Citation}` | Many items × attributes, or exact values worth scanning | One row (that becomes text) |
| `diagram` | `layout: "flow"\|"cycle"`, `nodes: 2–10 × {id, label ≤ 40}`, `edges: 1–14 × {from, to, label? ≤ 24}`, `page?: int` | Relationships or a pipeline (e.g., exemplars → reasoning chain → answer) | Anything a numbered list says just as well |
| `formula` | `latex ≤ 300`, `explanation ≤ 220`, `citation?: Citation` | A formula that actually appears in the document | Decorative math |
| `quiz` | `questions: 1–4 × {prompt ≤ 160, options: 3–4 × str ≤ 80, correct_index: int, explanation ≤ 220, citation: Citation}` | At the **end** of an explanatory answer (questions like "explain / how / why / what is the difference"), or when the user asks to be tested | Factual lookups ("who / when / which year") |
| `flashcards` | `cards: 3–8 × {front ≤ 60, back ≤ 200, page?: int}` | The user asks to study, review or memorize key terms | Otherwise |

### Restraint rules (put these in the system prompt *and* enforce them in `policy.py`)

They come from multimedia-learning research (Mayer): coherence, signaling, spatial contiguity, segmenting, the testing effect, and the seductive-details effect.

1. **No visual needed → plain text.** For lookups, definitions, yes/no questions and short facts, set `needs_visual=false` with `components=[]`. Example: "Who wrote this paper?" → text only.
2. **No decorative visuals.** Every component must make a structure clear: a comparison, sequence, quantity or relationship. Never add a component only to make the answer look rich.
3. **Coherence.** No extra facts that weren't asked for. No repeating `answer_text` inside a component (redundancy).
4. **Signaling.** Titles say what to notice ("CoT helps only in large models"), not just the topic ("Results").
5. **Spatial contiguity.** Labels belong inside the chart or diagram (axis labels, units, node labels), not in a separate legend paragraph.
6. **Segmenting.** One idea per card or step. Use at most 3 components.
7. **Retrieval at the end.** If there is a `quiz`, it is the **last** component. Allow at most one quiz.
8. **The server never trusts model arithmetic.** If a value was not printed in the document, it may not appear in a chart or table.

**Server policy (`policy.py`, applied after validation and grounding):**

- If `needs_visual=false`, drop all components.
- Truncate to 3 components, keeping priority `comparison > steps > chart > table > diagram > formula > text`, with `quiz` always kept last if present.
- Move `quiz` to the end.
- A `chart` with fewer than 3 verified points becomes a `table` if at least 2 verified points remain; otherwise it is dropped and its points are added as text.
- A `table` with fewer than 2 verified rows is dropped and its content becomes text.
- A `comparison` whose items have different attribute key sets is dropped.
- Drop components with an empty `reason`, a duplicate `id`, or an unknown `type`.
- Every drop emits `COMPONENT_DROPPED` with a reason and is logged.

### Gemini schema compatibility

Pydantic's `model_json_schema()` produces some constructs Gemini may reject (for example `const` for `Literal`, deep `$defs`, `title` and `default`). Write `catalog.to_gemini_schema()`, which:

- turns `const` into a single-value `enum`;
- inlines or flattens `$ref` if needed;
- strips `title`, `default` and `examples`.

Unit-test it. If a live call returns `400 INVALID_ARGUMENT` for schema complexity, switch to **plan-then-fill mode** (set `SCHEMA_MODE=plan`):

- Call 1 returns `{answer_text, needs_visual, plan: [{type, intent}] ≤ 3}`.
- Then one call per planned component, each using only that component's schema.
- Emit `COMPONENT_PLANNED` after call 1.

Implement both modes behind the flag. `single` is the default.

## 5. Grounding (server-side verification)

On upload, extract text **per page** with **pdfplumber** (MIT license). Avoid PyMuPDF unless needed: it is AGPL, which matters for a company. Build two text layers for each page:

- `visible_text`: characters whose font size is at least 4 pt, whose fill colour is not white or near-white (luminance below 0.9), and which sit inside the page's crop box.
- `all_text`: every character.

**Grounding uses `visible_text` only.** Hidden text may reach the model, but it can never verify a claim.

**Normalization (`grounding.normalize`)** is applied to both the quote and the page text:

- Unicode **NFKC** (this also folds Arabic presentation forms).
- Arabic-Indic digits `٠١٢٣٤٥٦٧٨٩` (U+0660–0669) and Extended `۰–۹` (U+06F0–06F9) → `0–9`.
- Arabic decimal separator `٫` (U+066B) → `.`; Arabic thousands separator `٬` (U+066C) and `,` between digits → removed; `٪` (U+066A) → `%`.
- Remove tashkeel (U+064B–U+065F, U+0670) and tatweel (U+0640). Unify `أ إ آ` → `ا`, `ى` → `ي`, `ة` → `ه`.
- Join words hyphenated across line breaks (`reason-\ning` → `reasoning`). Collapse whitespace and lowercase Latin letters.

**Checks:**

1. **Quote check.** Compute `rapidfuzz.fuzz.partial_ratio(norm(quote), norm(page_visible_text)) ≥ 90` on the cited page. If that fails, try the pages next to it (±1) and fix the page number if one matches.
2. **Number check** (for chart points and table rows). Every number in `value` (and every numeric cell) must appear in the normalized quote, allowing ±0.05 absolute difference or a rounding difference of one decimal place. Percent and plain forms (`56.9%` vs `56.9`) count as equal.
3. **Outcome per component.** All checks pass → `verified`. Some items dropped but the minimum counts remain → `partial` (the UI shows a "some values removed" note). Otherwise apply the policy downgrade.
4. **Scanned or no-text pages** (no extractable text): the component is marked `unverified` and shows the badge "لم يتم التحقق / Not verified". It is never silently trusted.

**Cross-language note.** The CoT paper is in English. In an Arabic answer, labels and explanations are Egyptian Arabic, but **`citation.quote` stays verbatim English**. The UI shows quotes in an LTR island.

**UI.** Every cited value has a small page chip (`ص ١٢` / `p. 12`). Hovering or focusing it shows the quote, and clicking it opens a side panel showing that page's text with the quote highlighted. No PDF rendering is required; plain page text is enough.

## 6. Security requirements

| Threat (OWASP LLM Top 10 2025) | Control |
|---|---|
| LLM01 prompt injection hidden in the PDF | Assume prompt-level defenses fail (research shows "ignore instructions in the document" prompts don't meaningfully help). **Limit what an attack can do:** the model has **no tools**, the prompt holds **no secrets**, and output is only catalog data. Wrap the document in clear delimiters and state that it is untrusted data, but don't rely on it. Detect hidden text (tiny or white characters, text outside the crop box) and emit `WARNING HIDDEN_TEXT_DETECTED` with the affected pages. Grounding ignores hidden text. |
| LLM05 improper output handling (XSS) | **No `dangerouslySetInnerHTML` anywhere** (add an ESLint rule and a CI grep). React escapes all model strings. Markdown only through `react-markdown` **without** `rehype-raw`, using `allowedElements=['p','strong','em','ul','ol','li','code']`. **Never render model-supplied URLs, links or images.** Strip `http(s)://` strings into plain text. Diagrams use our own SVG layout from `{nodes, edges}`. **Do not use Mermaid.** (It has no RTL support and a history of XSS advisories. If you ever add it, pin a patched version and use `securityLevel: 'strict'`.) KaTeX with `trust: false`, `strict: 'warn'`, `maxSize: 10`, `maxExpand: 100`. |
| LLM09 misinformation | Grounding (section 5) plus "Not verified" badges. |
| LLM10 unbounded consumption | `slowapi` rate limit per IP (`RATE_LIMIT=10/minute` on `/api/ask`, `5/minute` on upload). `MAX_OUTPUT_TOKENS=4096`. Question length ≤ 500 chars. `MAX_QUESTIONS_PER_DOC=50`. Request timeout `REQUEST_TIMEOUT_S=45`, with fallback to text plus `RUN_ERROR`. |
| LLM07 system prompt leakage | The prompt contains no secrets. Assume it can leak. |
| Uploads | Limit to `MAX_UPLOAD_MB=20` and `MAX_PAGES=60`. Check magic bytes `%PDF-` as well as Content-Type. Reject files pdfplumber can't open, and reject encrypted files. Store files as `data/uploads/<uuid4>.pdf` outside any static directory. `doc_id` is a random UUID. Delete files older than 48 h on startup and every hour. |
| Key handling | `GEMINI_API_KEY` is read only by the backend. `.env` goes in `.gitignore`. Ship `.env.example`. A test greps the built `frontend/dist` for `AIza` and for the key value and must find nothing. Never log the key or full PDF text (`LOG_RAW_OUTPUT=0` by default; when it's 1, raw model output is written to `data/logs/` for fixture creation). |
| Browser hardening | In e2e/prod, FastAPI serves the built frontend from one origin and sends these headers: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; frame-ancestors 'none'`, plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. CORS allows only `CORS_ORIGINS` (the Vite dev origin) in dev. |
| Data residency notice | A footer badge: "Demo uses Google Gemini API — production can run on a self-hosted model." |

## 7. Latency design and targets

- `THINKING_LEVEL=low` (env). Allowed values: `minimal|low|medium|high`. Never send `thinking_budget` as well.
- **Upload once.** On `/api/documents`, upload the PDF to the Gemini **Files API**. Keep `file_uri` per `doc_id` and SHA-256, and reuse it until 47 h old, then re-upload.
- **Warm the cache.** After upload, start one cheap background `count_tokens` call (not a generation) to log the real token count. Put the system prompt + catalog + file **first** in `contents` and keep this prefix byte-for-byte stable so implicit caching can hit. Optionally set `ENABLE_EXPLICIT_CACHE=1` to create an explicit cache (TTL 1 h) for the doc. Log `cached_content_token_count` on every call.
- **Stream** with `generate_content_stream`. Accumulate the deltas and parse the partial JSON on each delta with `jiter.from_json(buf, partial_mode="trailing-strings")` (verify that this API exists; if not, use a small bracket-depth scanner):
  - Emit `TEXT_MESSAGE_CONTENT` with the new characters of `answer_text` as they arrive.
  - Treat component *i* as complete when `components` has more than *i*+1 items or the whole JSON parses completely. Then run Pydantic validation → grounding → policy, and emit `COMPONENT` or `COMPONENT_DROPPED`.
  - Emit `COMPONENT_PLANNED` as soon as a new component's `type` appears, so the client can show a skeleton.
- **App answer cache.** Key = `sha256(pdf) + normalize(question) + lang + model + PROMPT_VERSION`. Store final validated events in SQLite (`data/cache.sqlite`). A cache hit replays the events immediately with `cached: true`.
- **Fallback.** On 429/503: exponential backoff with jitter (2 retries), then retry once on `FALLBACK_MODEL` and emit `WARNING FALLBACK_MODEL_USED`. On timeout: send whatever `answer_text` has arrived, then `RUN_ERROR`.
- **Client.** Show skeletons that match the planned type (chart, cards, table shapes), an elapsed-time counter, and a "Thinking…" state before the first token. Respect `prefers-reduced-motion`.

**Targets.** These are goals to *measure*, not promises. No official low-thinking latency figure exists.

## 8. Bilingual and RTL details

- **Toggle.** A header button `عربي | English` sets `<html lang dir>` (`ar` + `rtl`, or `en` + `ltr`), switches UI strings (`frontend/src/i18n/{ar,en}.json`), and sends `lang` to `/api/ask`. Remember the choice in `localStorage` inside try/catch. The default is Arabic.
- **Prompting.** For `lang=ar`: "Answer in Egyptian colloquial Arabic (عامية مصرية), clear and friendly. Keep technical terms in English where Egyptians use them (e.g., Chain-of-Thought, prompt, GSM8K). Quotes must be verbatim from the document." For `lang=en`: plain, simple English.
- **Per-component direction.** Each component root gets `dir={props.lang === 'ar' ? 'rtl' : 'ltr'}` and `lang`. Every model-generated string is rendered with `dir="auto"`. Mixed tokens (numbers with units, English terms, model names like "PaLM 540B") go in `<bdi>`.
- **Fonts.** Self-host **IBM Plex Sans Arabic** (`@fontsource/ibm-plex-sans-arabic`, weights 400/600). It includes Latin glyphs. Font stack: `"IBM Plex Sans Arabic", "Noto Sans Arabic", system-ui, sans-serif`. Pass the same font family to Recharts text. **No `letter-spacing` on Arabic text**, because it breaks letter joining. Self-hosting also keeps screenshots stable.
- **Digits.** Use Western digits in both languages by default (`Intl.NumberFormat('ar-EG-u-nu-latn')`), so values match the English source quotes. Add a setting `DIGITS=arab` that uses `ar-EG` (Arabic-Indic digits) for display only. Grounding always works on normalized Western digits.
- **Charts (Recharts).** Keep the data order logical and mirror only the display. In RTL use `<XAxis reversed />` and `<YAxis orientation="right" />`, give the tooltip content `dir="rtl"`, and keep the legend at the start side. Check in the screenshot test that the first category is the rightmost tick in RTL.
- **Tables.** Native `<table>` inside `dir="rtl"` mirrors column order. Numeric cells use `text-end` and `<bdi>`.
- **Diagram.** Write our own SVG layout. For `flow`, use a simple layered layout (or `dagre` if needed) that runs right→left in RTL and left→right in LTR. For `cycle`, place nodes on a circle and go clockwise in LTR, counter-clockwise in RTL. Labels are SVG `<text>` with `direction` set and the font applied. Arrowheads mirror.
- **KaTeX.** Wrap each formula in `<span dir="ltr" class="ltr-island">` and add the CSS `.katex-display>.katex>.katex-html{direction:ltr}`.
- **Icons.** Mirror directional icons (arrows, chevrons, "next") in RTL with `rtl:-scale-x-100`. Don't mirror neutral icons.
- **Quotes** are always shown in an LTR island when the document is English.

## 10. Provider adapter

```python
class LLMProvider(Protocol):
    name: str
    async def prepare_document(self, doc: StoredDoc) -> ProviderDocHandle: ...   # Files API upload / or extracted text
    async def stream_structured(self, *, system: str, doc: ProviderDocHandle, question: str,
                                schema: dict, lang: str, max_output_tokens: int) -> AsyncIterator[ProviderDelta]: ...
    async def stream_text(self, *, system: str, doc: ProviderDocHandle, question: str,
                          lang: str, max_output_tokens: int) -> AsyncIterator[ProviderDelta]: ...
    async def count_tokens(self, doc: ProviderDocHandle) -> int: ...
# ProviderDelta = {text_delta: str | None, usage: Usage | None, finish_reason: str | None}
```

- `GeminiProvider`: `google-genai`, `MODEL`, `FALLBACK_MODEL`, `THINKING_LEVEL`, `MEDIA_RESOLUTION=medium`.
- `OpenAICompatProvider`: `OPENAI_COMPAT_BASE_URL`, `OPENAI_COMPAT_MODEL`, `OPENAI_COMPAT_API_KEY` (optional). It sends **the extracted visible text with page markers** (`[[page 3]] …`) instead of the PDF file, and uses `response_format={"type":"json_schema","json_schema":{...}}`. Unit-test it with `respx`/`httpx` mocks only. No live server is required.
- `MockProvider`: used when `MOCK_LLM=1`. It replays fixtures (section 12) as deltas in chunks of about 40 characters, with `MOCK_DELAY_MS=30` between chunks and an initial delay of `MOCK_TTFT_MS=400`.
- Choose the provider with `LLM_PROVIDER=gemini|openai_compat|mock`. `MOCK_LLM=1` forces mock.
